# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Daywalker Auth: a multi-tenant auth service (Next.js 16 App Router, Postgres via Drizzle, Valkey) plus an npm-workspace SDK (`packages/sdk`, published as `@daywalker/auth`) and an example app (`examples/nextjs`). Docs are Markdown in `content/docs`, rendered by the app at `/docs`. `README.md` has the feature list and security model; `NEXT_STEPS.md` has working notes on recent work and gotchas.

## Commands

```bash
docker compose up -d                  # Postgres 16 + Valkey 8
cp .env.example .env                  # set MASTER_KEY (command in the file)
npm run db:migrate                    # apply drizzle/ migrations
npm run seed -- http://localhost:3001 # creates an instance; prints pk (public) and sk (shown once)
npm run bootstrap:platform            # once, for /dashboard; put PLATFORM_PUBLISHABLE_KEY in .env
npm run dev                           # service on :3000
npm run typecheck                     # tsc for the service AND packages/sdk
npm run db:generate                   # after editing src/lib/db/schema.ts (writes drizzle/NNNN_*.sql + meta snapshot)
```

There is no linter. Tests are end-to-end scripts (`scripts/*-e2e.ts`) that hit a **running server** (`BASE_URL`, default `http://localhost:3000`); there is no unit-test runner. Run one suite with `npm run test:<name>` (e.g. `test:saml`, `test:protection`) or `npx tsx scripts/<name>-e2e.ts`.

To run suites, build and start the service first: `npm run build`, then `next start` with `ALLOW_INSECURE_TRANSPORT=1 WEBHOOK_ALLOW_PRIVATE=1 OAUTH_TEST_BASE_URL=http://localhost:3999` plus the Twilio/Turnstile/Pwned test vars from `.github/workflows/ci.yml`. The test process itself must **not** have `WEBHOOK_ALLOW_PRIVATE` set (the SSRF checks would pass for the wrong reason), as CI does with `env -u`. `test:sdk` additionally needs `examples/nextjs` running on :3001 with seeded keys. `test:all` lists suites explicitly in `package.json`; CI (`.github/workflows/ci.yml`) has its own list. **A new suite must be added to both**, plus its `test:<name>` script. Suites use a local `check(name, ok)` helper and create their own instance via `seedInstance` in `scripts/seed.ts`; mock IdP/Twilio/Turnstile servers are started by the suites on fixed ports.

## Architecture

**Layout.** `src/app/v1/**` are API route handlers (thin); logic lives in `src/lib/**`, mostly `src/lib/auth/*`. Hosted pages are `src/app/(auth)/*`, `account`, `dashboard`, `docs`. Schema is one file, `src/lib/db/schema.ts`. Migrations are hand-numbered `drizzle/00NN_*.sql` generated by drizzle-kit.

**Three API surfaces**, each with its own auth wrapper:
- Frontend API `/v1/client/*`: browser calls, identified by `x-publishable-key` + HttpOnly refresh cookie. `src/lib/auth/frontend.ts` resolves the instance, enforces the CSRF origin check (service origin or the instance's `allowedOrigins`) and CORS, and sets cookies.
- Backend API `/v1/users`, `/v1/sessions`, `/v1/organizations`, `/v1/webhooks`, `/v1/instance/*`, etc.: `Authorization: Bearer sk_...`, no CORS.
- Public: per-instance JWKS/OIDC discovery under `/i/:instanceId/`, SAML (`/v1/saml/:id/*`), SCIM (`/v1/scim/v2/:connectionId/*`, its own bearer token), OAuth callbacks.

All route handlers are wrapped in `handler()` from `src/lib/http.ts`: throw `errors.*`/`ApiError(status, code, msg)` for JSON errors, Zod errors become 422, anything else a generic 500. Error codes are public API (documented in `content/docs/api/errors.md`).

**Multi-tenancy.** Everything is scoped to an `instance` (a customer's auth tenant). Each has its own ES256 signing keys, settings, providers, origins. Sessions are a 60 s JWT (verified locally by apps via JWKS) backed by a refresh cookie; session state is cached in Valkey. `src/lib/auth/instance.ts` caches instances, so settings updates must not write back stale cached objects (a past bug in protection updates).

**Encryption at rest is central.** `src/lib/crypto.ts` derives subkeys from `MASTER_KEY` via HKDF; PII fields are AES-256-GCM with table/column/row-id as AAD; emails are found through a keyed HMAC blind index (`INDEX_KEY`, scoped per instance). `src/lib/crypto-fields.ts` (`ENCRYPTED_FIELDS`) is the registry that `src/lib/rotate.ts` uses to re-encrypt everything for master-key rotation. **When adding any new encrypted column, add it to that registry** or rotation will silently skip it (`masterkey-e2e` checks this).

**Sign-in is layered policy.** Sign-in paths (password, email code/magic link, passkey, OAuth, SAML) converge on `complete-sign-in.ts`/`sessions.ts`. Cross-cutting policy modules sit in front of them: `sso-policy.ts` ("SSO required" per domain, with a `createSession` backstop), `signup-protection.ts` (domain lists, throwaway emails, Turnstile; fails closed), `two-factor-policy.ts` (required 2FA app-wide or per org; `issueToken` refuses, sessions stay for enrollment), `breach.ts`. A new sign-in path must go through these, not around them.

**Outbound HTTP to developer-supplied URLs** (webhooks, SAML metadata, OIDC discovery, Turnstile) must use `src/lib/net-guard.ts` (`checkPublicUrl`, `guardedFetch`) for SSRF protection.

**Enterprise bits.** SAML (`saml.ts`, `saml-logout.ts`), SCIM (`scim*.ts`, `src/lib/scim-http.ts`), OAuth providers are a registry in `oauth-providers.ts` (adding one = a `DEFS` entry, labels, a DB enum migration, `parseSettings`). Webhooks (`webhooks.ts`) run a delivery loop inside the server (`WEBHOOK_WORKER=0` disables; started from `src/instrumentation.ts`).

**Security headers** are set in `src/proxy.ts`: credential-handling pages get a per-request nonce CSP; docs/home are static. New third-party embeds need a CSP entry there.

**SDK** (`packages/sdk/src`): `core` (browser client), `react` (hooks + drop-in components + `styles.css`), `server` (`verifyToken`, `verifyWebhook`, backend client), `nextjs` (`auth()`, `authProxy`). Exported straight from TS source (no build step). When a feature adds an API, update the SDK types/methods, the matching `content/docs` page, and the roadmap/`NEXT_STEPS.md` as the recent commits do.

## Production-mode constraints

When `NODE_ENV=production`, startup refuses non-HTTPS `APP_URL`, Postgres without `sslmode=require|verify-full`, and Valkey without `rediss://`. Tests relax this with `ALLOW_INSECURE_TRANSPORT=1`. Client IP for rate limits comes from `X-Forwarded-For` via `TRUST_PROXY_HOPS`.
